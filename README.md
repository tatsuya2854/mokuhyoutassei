# ヤルコト

**「今日何をすればいいか」で迷う状態を、なくす。**

目標金額と期限を答えると、稼ぐ手段を **1つに決め切って**、毎日やることを指示してくる「上司役」のウェブアプリ。
計画 → 実行 → 記録 → 分析 → 改善のループを、こちらから強制的に回します。

<p align="center">
  <em>スマホ前提・インストール不要・アカウント登録不要・完全無料で動きます。</em>
</p>

---

## なにが違うのか

よくあるタスク管理アプリは「タスクを入れる箱」を渡してきます。でも本当に困っているのは、**何をタスクにすればいいか分からない**ところです。

ヤルコトは逆から始めます。

| よくあるアプリ | ヤルコト |
| --- | --- |
| 選択肢を並べて「どれにしますか？」 | 条件から採点して**1つに決め切る**。却下理由も全部出す |
| タスクは自分で考えて入れる | 目標から逆算して**毎日自動で降ってくる** |
| できなかったタスクが積み上がる | **翌日の量を自動で減らす**。止まった原因ごと潰す |
| 記録を見るのは自分 | **数字を読んで次の一手を言ってくる** |

## 使う流れ

### 1. 6問のヒアリング

| # | 聞くこと | なぜ聞くか |
| --- | --- | --- |
| 01 | 目標金額（月いくら／合計いくら） | 必要な月収ラインを確定させるため |
| 02 | 期限 | 期限のない目標は願望でしかないため |
| 03 | 週の可処分時間・稼働日数 | 1日あたりの作業量を現実的に決めるため |
| 04 | 使えるスキル | ゼロから覚える時間を計画に含めないため |
| 05 | 初期費用 | 資金が要る手段を最初から外すため |
| 06 | やりたくないこと | 続かない手段を**候補から完全に除外**するため |

### 2. 手段を1つに確定する

10種類の手段（プレイブック）を5つの軸で採点し、最高点の1つだけを提示します。

```
スコア = 時間の適合 ×20 + 予算の適合 ×10 + スキル適合 ×28
       + 期限内の到達見込み ×30 + 目標規模との相性 ×12
       −（「やりたくないこと」に該当したら実質除外）
```

収録している手段：

AI業務自動化の受託 / Web制作の受託 / 特化メディア×アフィリエイト / ショート動画の運用 /
デジタル商品販売 / SNS運用代行 / Webライティング受託 / デザイン受託 / 物販 / コーチング・個別相談

結果画面では、**選んだ理由・先に言っておくリスク・他を却下した理由**まで出します。
目標設定に無理がある場合は、忖度せずそう言います（例：「週3時間で月10万は正直かなり無理がある」）。

### 3. マイルストーン → 日次タスクに自動分解

期限までを4フェーズに分割します。

| フェーズ | ゴール |
| --- | --- |
| 1. 土台づくり | 何で・誰に・いくらで売るかを確定させる |
| 2. 立ち上げ | 売り物と入口を用意して、世に出す |
| 3. 初収益 | 1円目を取りにいく。売れる型を見つける |
| 4. 拡大・仕組み化 | 当たった型に寄せて、作業を減らしながら増やす |

各手段は **一度きりのステップ**（例：「競合の価格を10件調べる」）と、
**くり返すルーティン**（例：「営業DMを5件送る」週4回）を持っています。
その日の作業枠に収まるよう、繰越 → ステップ → ルーティンの順に詰めていきます。

### 4. 毎日、その日やることを指示する

進捗と連続実行日数から口調が変わります。順調なら褒め、止まっていれば詰めます。

> **今日はこれだけ。**
> スタート地点。ここで一番大事なのは、完璧にやることじゃなくて「得意な制作領域を1つに決める」を今日中に終わらせること。
> 今日の総量は120分。2件。

### 5. 実行結果を記録して、翌日を自動調整

1日を締めると、完了状況・収益・所要時間・気づきを記録し、翌日の負荷を調整します。

| 状況 | 調整 |
| --- | --- |
| 3日連続でゼロ | 1日の量を**半分に削る**。「まず1個」に戻す |
| 直近の消化率が45%未満 | 20%減らす。積み残しによる自己嫌悪ループを止める |
| 消化率90%以上が3日続く | 15%増やす（上限は基準の1.6倍） |
| それ以外 | 維持 |

未完了タスクは翌日の**先頭**に「繰越」として回ります。
1日の枠に収まらない大きいステップは、枠のぶんだけ進める形で分割され、チェックを入れるまで毎日先頭に出続けます。

### 6. 分析して、次の一手を言う

数字だけ出して終わりにはしません。必ず「だから何をするか」まで書きます。

> 期間は45%消化、計画は22% → 23ポイント遅れてる。タスクを減らすか、可処分時間を増やすかの二択。精神論では埋まらない。

> 期間を3割超えて収益ゼロ → 作業はしてるけど「売る行為」が足りてない可能性が高い。まず提案・出品・告知の数を今週の最優先にする。

## 動かす

```bash
npm install
npm run dev          # http://localhost:5173
```

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバー |

| `npm run preview` | ビルド結果をローカル確認 |
| `npm test` | ロジックのテスト（65件） |
| `npm run lint` | oxlint |
| `npm run typecheck` | 型チェック |
| `npm run check` | lint → 型 → テスト → ビルドを一括 |

## 公開する

ビルド成果物は静的ファイルだけなので、どこにでも置けます。

### GitHub Pages

`main` に push すると `.github/workflows/deploy.yml` が自動でデプロイします。
リポジトリの **Settings → Pages → Source** を **GitHub Actions** に設定してください。

サブディレクトリ配信（`https://<user>.github.io/<repo>/`）に対応するため、
ワークフローは `VITE_BASE=/<repo>/` を渡してビルドします。

### Vercel / Netlify / Cloudflare Pages

| 項目 | 値 |
| --- | --- |
| Build command | `npm run build` |
| Output directory | `dist` |
| Node version | 20 以上 |

`netlify.toml` と `vercel.json` を同梱しているので、リポジトリを繋ぐだけで動きます。

### 自前のサーバー

`npm run build` して `dist/` をそのまま配信するだけです。SPAなので、
不明なパスは `index.html` にフォールバックさせてください（同梱の設定ファイルはその指定込みです）。

## 設計

### 技術選定

| 選んだもの | 理由 |
| --- | --- |
| React 19 + TypeScript + Vite | ビルドが速く、静的ホスティングにそのまま載る |
| Tailwind CSS v4 | デザイントークンをCSSで一元管理。スマホ前提の調整が速い |
| zustand + localStorage | サーバーもログインも不要。開いた瞬間から使える |
| Vitest | 判断ロジックをUIから切り離して高速に検証する |

**上司役はLLM APIを呼ばず、決定論的なルールエンジンで実装しています。**
APIキー不要・課金なし・オフライン動作・即レスポンスで、同じ状況なら必ず同じことを言う（＝上司の判断がブレない）ためです。

### ディレクトリ

```
src/
├── domain/              ← UIから独立した判断ロジック（ここが本体）
│   ├── playbooks.ts     手段カタログ 10種（ステップ／ルーティン定義）
│   ├── decide.ts        手段決定エンジン（採点・却下理由・達成可否判定）
│   ├── planner.ts       フェーズ分割・日次タスク生成
│   ├── adjust.ts        実績にもとづく翌日の負荷調整
│   ├── progress.ts      進捗・ペース・連続日数・収益の集計
│   ├── coach.ts         上司の発話生成（朝の指示／締めの講評／示唆）
│   └── engine.test.ts   65件のテスト
├── screens/             今日 / 計画 / 記録 / 分析 / 設定 / ヒアリング / 診断結果
├── components/          UIプリミティブ・アイコン
├── store/               zustand ストア（localStorage 永続化）
└── lib/                 日付・スタイルユーティリティ
```

### テスト

`npm test` で65件が走ります。単体だけでなく、**90日間のループを最後まで回す統合シミュレーション**を含みます。

- 全10手段で90日間、毎日必ずタスクが生成されること
- 完了したステップが二度と指示されないこと
- 全く動かない日が続いても計画が破綻せず、負荷が下限20分まで自動的に落ちること
- サボりと挽回が混ざっても数値が壊れないこと
- ルーティンの週あたり上限を超えないこと・週をまたぐとリセットされること

## データの扱い

記録は**その端末のブラウザ（localStorage）にだけ**保存されます。サーバーへの送信は一切ありません。
設定画面からJSONで書き出し／読み込みができるので、端末を移すときはそれで移行してください。

---

## 制約

- 収益の見込み額（ramp）は一般的な目安であり、達成を保証するものではありません
- 端末をまたいだ同期はありません（手動エクスポート／インポートのみ）
- 通知機能はありません。開いたときに指示が出る形です
