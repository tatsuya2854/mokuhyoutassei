# ヤルコト

**先が見えなくて不安なのは、今日が空白だから。**

いま何がしんどいかを選ぶだけで、それを目標に翻訳し、手段を **1つに決め切って**、
最終目標から逆算して月・週・今日に落とし込む **AI秘書兼マネージャー**。
計画 → 実行 → 記録 → 分析 → 改善のループを、こちらから強制的に回します。

対象は **18〜30歳** くらいの、進路やお金に不安がある人。

いちばん大事にしている設計が1つあります。

> **未完了を失敗にしない。**
> 3個中1個しか終わらなくても、その1個が最重要なら十分な前進として扱う。
> 消化率だけで採点すると、人は「できなかった日」を数えるようになって止まるからです。

<p align="center">
  <em>スマホ前提・インストール不要・アカウント登録不要。最初の7日間は全機能が無料。</em>
</p>

---

## なにが違うのか

よくあるタスク管理アプリは「タスクを入れる箱」を渡してきます。でも本当に困っているのは、**何をタスクにすればいいか分からない**ところです。

ヤルコトは逆から始めます。

| よくあるアプリ | ヤルコト |
| --- | --- |
| 選択肢を並べて「どれにしますか？」 | 条件から採点して**1つに決め切る**。却下理由も全部出す |
| タスクは自分で考えて入れる | 目標から逆算して**毎日自動で降ってくる** |
| できなかったタスクが積み上がる | **翌日の量を自動で減らす**。止まった原因ごと潰す |
| 記録を見るのは自分 | **数字を読んで次の一手を言ってくる** |
| 未完了は赤くなって残り続ける | **1個でも本命が終われば「今日は前進」** |
| 「後で」は翌日にずらすだけ | 残り時間・曜日の癖・重さを見て**いちばん終わりそうな日に置き直す** |

## 使う流れ

### 1. 「いま何がしんどい？」から始める

いきなり金額を聞きません。「何がやりたいか分からない」人に月収を聞いても、最初の画面で手が止まるからです。

| 選んだ不安 | 翻訳される目標 |
| --- | --- |
| お金が足りない・将来が不安 | **お金**（月◯円 / 合計◯円） |
| 就職・進路が決まらない | **実績**（人に見せられるものを◯本） |
| 何がやりたいか分からない | **探索**（◯つ試して2週間後に1つに絞る） |
| 周りより遅れてる気がする | **継続**（◯日つづける） |
| 何をやっても続かない | **継続** |
| 武器になるスキルがない | **スキル**（言い切れるものを1つ） |

選んだ瞬間に、上司が受け止めを返します。

> **就職・進路が決まらない**
> 足りないのは「やる気」じゃなくて、人に見せられるものが1つも無いこと。作れば終わる。

続く質問は**目標タイプによって数が変わります**。答える気力が一番少ない人ほど、質問が少なくなる設計です。

| 目標タイプ | 質問数 | 聞くこと |
| --- | --- | --- |
| 継続 | **5問** | 不安 / 日数 / 期限 / 時間 / NG |
| 実績・スキル・探索 | **6問** | 上記 ＋ スキル |
| お金 | **7問** | 上記 ＋ 初期費用 |

### 2. 手段を1つに確定する

10種類の手段（プレイブック）を採点し、最高点の1つだけを提示します。
**採点の重みは目標タイプで変わります。**

| 目標タイプ | 時間 | 予算 | スキル | 収益の到達見込み | 手を動かす比率 |
| --- | --- | --- | --- | --- | --- |
| お金 | 20 | 10 | 28 | **30** | 12 |
| 実績 | 20 | 10 | **40** | 0 | 30 |
| スキル | 15 | 5 | **45** | 0 | **35** |
| 継続 | **30** | 10 | 40 | 0 | 20 |

「やりたくないこと」に該当する手段は、どの目標タイプでも実質除外されます。

**「何がやりたいか分からない」を選ぶと、決め切りません。** 上位3手段を並行で2週間試して、
手が動いた方を残します。探索中は各タスクに手段名が付くので、何を試しているか分かります。

> 【物販（せどり・転売）】扱うジャンルを1つ決める
> 【ショート動画の運用】伸びてるアカウントを30個分析する

収録している手段：

AI業務自動化の受託 / Web制作の受託 / 特化メディア×アフィリエイト / ショート動画の運用 /
デジタル商品販売 / SNS運用代行 / Webライティング受託 / デザイン受託 / 物販 / コーチング・個別相談

結果画面では、**選んだ理由・先に言っておくリスク・他を却下した理由**まで出します。
目標設定に無理がある場合は、忖度せずそう言います（例：「週3時間で月10万は正直かなり無理がある」）。

### 3. マイルストーン → 日次タスクに自動分解

期限までを4フェーズに分割します。**フェーズの名前と中身も目標タイプで変わります。**

| # | お金 | 実績 | スキル | 継続 |
| --- | --- | --- | --- | --- |
| 1 | 土台づくり | 決める | 決める | 決める |
| 2 | 立ち上げ | 作り始める | 基礎 | 助走 |
| 3 | 初収益 | 完成させる | 作って覚える | 軌道に乗せる |
| 4 | 拡大・仕組み化 | 見せる | 使えるようにする | 定着 |

就職が不安な人に「何で・誰に・いくらで売るかを確定させる」と言っても、その不安は減りません。

さらに、**目標タイプに合わないタグのタスクは出しません。**

| 目標タイプ | 出さないタスク |
| --- | --- |
| 実績 | 営業・販売・出品・仕入・運用・実施 |
| スキル・探索 | 上記 ＋ 集客・投稿・拡大・仕組み |

絞った結果タスクが枯れる手段では、安全弁として絞り込みを無視します。
絞って出さないステップは「立ち上げ完了」の分母からも外れるので、
永久に未完了のまま残って改善サイクルに進めなくなることはありません。

各手段は3種類の仕事を持っています。

| 種類 | 役割 | 例 |
| --- | --- | --- |
| **ステップ** | 一度きりの立ち上げ作業 | 「競合の価格を10件調べる」 |
| **ルーティン** | 週N回くり返す反復の手 | 「営業DMを5件送る」週4回 |
| **改善サイクル** | 立ち上げ後にまわす改善の手 | 「営業の型を1つ変えて10件送る」 |

その日の作業枠に収まるよう、繰越 → ステップ → 週次レビュー → ルーティンと改善サイクル（交互）
の順に詰めていきます。

### 4. 立ち上げが終わったら、状況に合わせて指示を変える

ここが一番こだわった部分です。立ち上げステップを消化しきると、多くのアプリは
「同じタスクの無限ループ」になります。ヤルコトは**実際の結果を見て指示の中身を変えます**。

| 状況 | 出てくる改善サイクル |
| --- | --- |
| 収益ゼロ | 「営業の型を1つ変えて10件送る」「販売ページの冒頭3行を書き直す」＝**売る量と入口** |
| 収益あり | 「既存客に追加提案を1件出す」「内容を加筆して値上げする」＝**単価と仕組み** |
| 消化率が落ちている | 「30分で終わる改修を1件片付ける」＝**着手のハードルを下げる** |
| 常時 | 「実工数を記録して時給を出す」＝**計測** |

180日回したときの実測で、立ち上げ後の指示は**全10手段で8〜13種類に散り**、
収益が発生した時点で「売る量を増やす」系から「単価・仕組み」系へ自動的に切り替わります。

加えて、毎週の初回稼働日に**週次レビュー**が差し込まれます。先週の数字を突きつけたうえで、
「今週のテーマ」を1つに絞ります。

| 状況 | 今週のテーマ |
| --- | --- |
| 探索中 | ◯つを実際に触ってみる |
| 先週の消化率が40%未満 | 量を絞って、毎日ゼロをなくす |
| 立ち上げ前 | （フェーズ名から生成） |
| **継続**の目標 | ゼロの日を作らない |
| **スキル**の目標 | 読むのをやめて、手を動かす |
| **実績**・まだ完成ゼロ | 粗くていいから、1つ完成させる |
| **実績**・完成あり | 作ったものを、人が見られる場所に置く |
| **お金**・収益ゼロ | 「売る動き」の回数を今の倍にする |
| **お金**・必要額の半分未満 | 当たった型を特定して、そこに寄せる |
| **お金**・必要額に近い | 単価を上げるか、件数を増やすか決める |
| **お金**・必要額を達成 | 再現性をつくる。作業を減らしながら維持する |

そして、**今週のぶんを全部やり切った日は、作業をでっち上げません。**
「今週のぶんは終わってる。休むか、前倒しするか決める」とだけ出します。

### 5. 毎日、その日やることを **3〜5個に絞って** 指示する

1日に出すタスクは最大5件。そのうち **本命（must）はちょうど1つ** です。

> **今日はこれだけ。**
> スタート地点。ここで一番大事なのは、完璧にやることじゃなくて「得意な制作領域を1つに決める」を今日中に終わらせること。
> 今日の本命は「得意な制作領域を1つに決める」。これさえ終われば、残りが消えても今日は前進扱いでいい。
> 今日の総量は120分。2件。

進捗と連続実行日数から口調が変わります。順調なら褒め、止まっていれば詰めます。

#### その日の判定

| 状況 | 判定 | 失敗扱い？ |
| --- | --- | --- |
| 全部終わった | 全部消化 | — |
| **本命が終わった**（他が残っていても） | **今日は勝ち** | **しない** |
| 動いたが本命が残った | 動いたけど本命が残った | しない |
| 本命なしで半分以上 | 今日は前進 | しない |
| 1件も動いていない | 今日はゼロ | する |

> **今日は勝ち。**
> 1/3件。でも今日の本命は終わってる。残った2件は「やれなかった分」じゃなくて
> 「今日やらなくてよかった分」。ちゃんと組み直して明日以降に回す。

#### ワンタップ／スワイプで逃がす

| 操作 | 意味 |
| --- | --- |
| **左へスワイプ** | 今日はパス |
| **右へスワイプ** | 再計画 |
| 行をタップ → ボタン | 同じことがタップでもできる（スワイプが使えない環境向け） |

どちらも**単に翌日へずらしません**。期限までの残り・曜日ごとの消化率・タスクの重さ・
これまで何回逃げたかを見て、いちばん終わりそうな日に置き直し、その理由まで返します。

> 9月27日(土)に置き直した — 土曜はよく消化できてる日。重いタスクを落としがちだから、余裕のある日に寄せた

3回目の先送りになると置き直す代わりに問い返します。

> 3回目の先送り。明日の先頭に戻すけど、やらないなら消した方がいい
> → [もうやらない] [いや、やる]

**自分でパスしたタスクは、その日の分母から外れます。** 判断したことが減点になるのは変だからです。
置き直し先の日が来るまで、カタログからも再生成されません。

### 6. 実行結果を記録して、翌日を自動調整

1日を締めると、完了状況・収益・所要時間・気づきを記録し、翌日の負荷を調整します。

| 状況 | 調整 |
| --- | --- |
| 3日連続でゼロ | 1日の量を**半分に削る**。「まず1個」に戻す |
| 直近の消化率が45%未満 | 20%減らす。積み残しによる自己嫌悪ループを止める |
| 消化率90%以上が3日続く | 15%増やす（上限は基準の1.6倍） |
| それ以外 | 維持 |

未完了タスクは翌日の**先頭**に「繰越」として回ります。
1日の枠に収まらない大きいステップは、枠のぶんだけ進める形で分割され、チェックを入れるまで毎日先頭に出続けます。

### 7. 行動データを長期記憶として持つ

別のストレージは持ちません。**日次ログがそのまま記憶**なので、記録と記憶がズレることが原理的に起きません。

| 覚えること | 次にどう効くか |
| --- | --- |
| 見積りと実績のズレ | 以降の見積りを実測倍率で補正する（元の見積りも残す） |
| タグ別のズレ | 「執筆だけ2倍かかる」を個別に学習する |
| 曜日別の消化率 | 置き直し先を、よく消化できている曜日に寄せる |
| タスクの重さ別の完了率 | 大きい塊が苦手な人には、重いものを余裕のある日に寄せる |
| 先送り回数 | 2回以上逃げているタスクを名指しする |
| 本命の達成率 | 「一番大事な1個を朝いちばんに」と言い方を変える |

分析画面の **「あなたについて分かったこと」** に、そのまま言葉で出します。

> 見積りより40%多く時間がかかってる → 以降の見積りを40%増しで出すようにした。盛ってるんじゃなくて、あなたの実測。

> 月曜の消化率67%に対して土曜は40% → 重いタスクは月曜に寄せる。土曜は軽くする。

### 8. AI秘書と話す

「時間がない」と打つだけで、今日のぶんを組み直します。

> **時間がない**
> 了解。今日はそういう日ってだけ。
> やるのは「制作フローを図にする」の1個だけでいい。55分。
> 残りは置き直すから、気にしなくていい。
> ゼロと1は全然ちがう。1にしてから寝よう。
> → [今日はパス：ポートフォリオサイトを公開する]

返答に付くボタンはその場で実行できます（完了にする／今日はパス／再計画）。

音声にも対応しています（読み上げ・音声入力）。
**特定のサービスに固定していません。** 既定はブラウザ内蔵（Web Speech API）で、
`VoicePort` を差し替えれば別のサービスに切り替えられます。

### 9. 分析して、次の一手を言う

数字だけ出して終わりにはしません。必ず「だから何をするか」まで書きます。

> 期間は45%消化、計画は22% → 23ポイント遅れてる。タスクを減らすか、可処分時間を増やすかの二択。精神論では埋まらない。

> 期間を3割超えて収益ゼロ → 作業はしてるけど「売る行為」が足りてない可能性が高い。まず提案・出品・告知の数を今週の最優先にする。

## 公開する

ビルド成果物は静的ファイルだけなので、どこにでも置けます。

### GitHub Pages

`main` に push すると `.github/workflows/deploy.yml` が自動でデプロイします。
リポジトリの **Settings → Pages → Source** を **GitHub Actions** に設定してください。

サブディレクトリ配信（`https://<user>.github.io/<repo>/`）に対応するため、
ワークフローは `VITE_BASE=/<repo>/` を渡してビルドします。

### Cloudflare Pages

リポジトリを繋ぐだけで動きます。設定は以下。

| 項目 | 値 |
| --- | --- |
| Framework preset | None（または Vite） |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | （空のまま） |
| 環境変数 | 不要 |

ルート配信なので `VITE_BASE` は設定しません（既定値の `/` が使われます）。
SPAのフォールバックは `public/_redirects` が `dist/_redirects` として出力され、
Cloudflare Pages がそれを読みます。

### Vercel / Netlify

| 項目 | 値 |
| --- | --- |
| Build command | `npm run build` |
| Output directory | `dist` |
| Node version | 20 以上 |

`netlify.toml` と `vercel.json` を同梱しているので、リポジトリを繋ぐだけで動きます。

### 自前のサーバー

`npm run build` して `dist/` をそのまま配信するだけです。SPAなので、
不明なパスは `index.html` にフォールバックさせてください（同梱の設定ファイルはその指定込みです）。

## 外部サービスにつなぐ

そのままでは**どこにも通信しません**。つなぐときは環境変数でサーバーのURLを渡します。

| 環境変数 | 中身 | 使われ方 |
| --- | --- | --- |
| `VITE_BILLING_API` | 自前サーバーのURL | Stripe の Checkout / カスタマーポータル |
| `VITE_ASSISTANT_API` | 自前サーバーのURL | AI秘書を外部LLMに差し替える |

どちらも**URLであって、鍵ではありません**。未設定なら端末内で完結する実装に自動で落ちます。

### APIキーをフロントに置かない

これは方針ではなく、構造でそうなっています。

- フロントのコードにも、ビルド成果物（`dist/`）にも、秘密鍵は一切含まれていません
- Stripe の secret key / webhook secret は**サーバーの環境変数だけ**に置きます
- publishable key すら不要です（Checkout の URL はサーバーが作って返す形にしてあります）
- 認証はサーバーが発行する **HttpOnly Cookie** で行い、トークンを JS から触れる場所に置きません
- AI秘書を外部LLMに差し替える場合も、フロントは**自分のサーバーにしか**リクエストしません

サーバー側に必要な口は合計4つだけです。

```
GET  {VITE_BILLING_API}/subscription           -> Subscription | null
POST {VITE_BILLING_API}/checkout   {planId,cycle} -> { url }
POST {VITE_BILLING_API}/portal                 -> { url }
POST {VITE_ASSISTANT_API}/assistant {text,ctx} -> { text, actions? }
```

### 差し替えられるようにしてある3か所

| 口 | 既定の実装 | 差し替え先の例 |
| --- | --- | --- |
| `BillingPort` | ローカルのスタブ（課金しない） | Stripe（`src/billing/stripe.ts`） |
| `AssistantPort` | 端末内のルールエンジン | 自前サーバー経由のLLM |
| `VoicePort` | Web Speech API | 任意の音声認識・合成サービス |

いずれも「アプリ本体はインターフェースしか知らない」形なので、
決済やAIの都合がコアロジックに染み出しません。

## 設計

### 技術選定

| 選んだもの | 理由 |
| --- | --- |
| React 19 + TypeScript + Vite | ビルドが速く、静的ホスティングにそのまま載る |
| Tailwind CSS v4 | デザイントークンをCSSで一元管理。スマホ前提の調整が速い |
| zustand + localStorage | サーバーもログインも不要。開いた瞬間から使える |
| Vitest | 判断ロジックをUIから切り離して高速に検証する |

**上司役・AI秘書は、既定ではLLM APIを呼ばず決定論的なルールエンジンで動きます。**
APIキー不要・追加課金なし・オフライン動作・即レスポンスで、
同じ状況なら必ず同じことを言う（＝上司の判断がブレない）ためです。
外部LLMに差し替える口は用意してありますが、その場合も鍵はサーバー側に置きます。

### テスト

`npm test` で148件が走ります。単体だけでなく、**90〜180日間のループを最後まで回す統合シミュレーション**を含みます。

- 全10手段で90日間、毎日必ずタスクが生成されること
- 完了したステップが二度と指示されないこと
- 全く動かない日が続いても計画が破綻せず、負荷が下限20分まで自動的に落ちること
- サボりと挽回が混ざっても数値が壊れないこと
- ルーティン・改善サイクルの週あたり上限を超えないこと・週をまたぐとリセットされること
- 立ち上げ後180日回しても、指示がルーティンの繰り返しに戻らないこと
- 収益の有無で出てくる改善サイクルが切り替わること
- 立ち上げ作業そのもののルーティン（例：商品の本文執筆）が、完成後に出続けないこと
- 週次レビューが週に1回だけ入ること・状況でテーマが変わること
- 全ての不安が目標タイプに紐づいていること
- 実績づくりの目標で営業・販売タスクが**一度も出ない**こと（45日シミュレーション）
- 目標タイプ × 全10手段の全組み合わせで、30日間タスクが枯れないこと
- 絞り込んだステップが「立ち上げ完了」の分母から外れること
- 探索モードが複数手段を返し、14日で終わること
- お金以外の目標で「収益」「単価」「円」という言葉が出ないこと
- 3件中1件でも、それが本命なら「前進」と判定されること
- 自分でパスしたタスクが、採点の分母からも繰越からも外れること
- 置き直したタスクが、その日が来るまで**一切**出てこないこと（カタログからの再生成も含む）
- 1日に本命がちょうど1つしか出ないこと・5件を超えないこと
- 見積りと実績のズレを学習して、生成される見積りが実測に寄ること
- 締めていない日・未来の日が長期記憶に混ざらないこと
- 年払いが全プランちょうど2ヶ月ぶん無料であること
- 上位プランが下位プランの機能と上限を必ず含むこと
- 無料期間が切れたらFreeに落ちること
- AI秘書が同じ問いに同じ答えを返すこと・分からないときに適当に喋らないこと

## データの扱い

記録は**その端末のブラウザ（localStorage）にだけ**保存されます。
既定の構成（環境変数なし）では、**サーバーへの送信は一切ありません**。AI秘書との会話も端末内で完結します。
設定画面からJSONで書き出し／読み込みができるので、端末を移すときはそれで移行してください。

> **公開URLを変えるときは注意。** localStorage はサイト（オリジン）ごとに分かれているため、
> 例えば `github.io` から `pages.dev` に移ると記録は引き継がれず、初回ヒアリングからやり直しになります。
> 移行する前に設定画面から「書き出す」でバックアップを取り、移行先で「読み込む」で復元してください。
> 複数のURLを併用すると記録が分散するので、**使うURLは1つに決めてください**。

## 制約

- 収益の見込み額（ramp）は一般的な目安であり、達成を保証するものではありません
- 端末をまたいだ同期はありません（手動エクスポート／インポートのみ）
- 公開URLを変えると記録は引き継がれません（上記「データの扱い」を参照）
- 通知機能はありません。開いたときに指示が出る形です
- 改善サイクルは手段ごとに7種類。数年単位で回し続けると一巡します
- 既定のAI秘書はルールベースなので、想定外の聞き方には答えず聞き返します
- 音声はブラウザの対応状況に依存します（Web Speech API 非対応の環境ではボタンが出ません）
- `VITE_BILLING_API` を設定しない限り、決済は実際には走りません（プラン切り替えは端末内で完結します）
